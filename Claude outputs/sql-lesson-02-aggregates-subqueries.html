Агрегаты и NULL — вопрос с собеседования

◆
ПОЧЕМУ 15, А НЕ 10

SUM, AVG, MIN, MAX, COUNT(колонка) пропускают NULL, будто этой строки нет. Поэтому AVG = 30 / 2 = 15. Только COUNT(*) считает все строки. Чаще всего так и нужно: средняя оценка фильма считается по тем, кто поставил оценку. Но если NULL для вас означает «ноль», превращайте его в ноль явно — COALESCE в блоке 06.

!
ЛОВУШКА: SUM ОТ ПУСТОТЫ — ЭТО NULL, А НЕ 0

SELECT SUM(amount), COUNT(*) FROM payment WHERE amount > 100; вернёт NULL и 0. Платежей нет — COUNT честно говорит 0, а SUM говорит «не знаю». На фронтенде это превратится в null, и график нарисует дыру или напишет «NaN ₽». Лечение: COALESCE(SUM(amount), 0).

Главная ошибка новичка

◆
ПОЧЕМУ БАЗА ОТКАЗЫВАЕТСЯ

После группировки в группе PG-13 — 223 фильма, а в результате для неё одна строка. Какое из 223 названий туда поставить? База не угадывает. Правило: в SELECT при GROUP BY можно писать только колонки из GROUP BY и агрегаты. Хотите одно название на группу — скажите, какое: MIN(title) (первое по алфавиту), или используйте DISTINCT ON из прошлого урока. MySQL в старом режиме молча подставлял случайное значение — и это годами порождало «плавающие» баги в отчётах.

05 · Даты в отчётах

live-coding~8 мин

Почти любой график на дашборде — это «что-то по времени»: выручка по месяцам, регистрации по дням, нагрузка по часам. Для этого даты группируют.

В 2022 году платежей вдвое больше и средний чек выше (4.00 против 2.96 — проверьте сами в домашке). Такие скачки в реальных отчётах и ищут глазами на графике, а потом выясняют причину запросами.

Часовой пояс меняет ответ

◆
ПОЧЕМУ ТАК

TIMESTAMPTZ хранит момент во времени (внутри — в UTC). При выводе и при EXTRACT/date_trunc база переводит его в часовой пояс сессии. Момент один и тот же, а «час» и даже «день» — разные. Правило из прошлого урока в действии: храним в TIMESTAMPTZ (UTC), а в локальное время переводим как можно позже — на клиенте через Intl.DateTimeFormat или в запросе явно, если отчёт «по московскому времени».

☺
ДАТЫ — ЭТО БОЛЬНО

31 декабря 2008 года все плееры Microsoft Zune 30 ГБ в мире одновременно зависли на сутки: в коде, считавшем дни года, не учли високосный год, и цикл стал бесконечным. Есть даже известный список «заблуждений программистов о времени»: «в сутках всегда 24 часа» (нет — переход на летнее время), «часовой пояс — это целое число часов» (нет — Индия +5:30, Непал +5:45). Мораль: даты не считаем руками — используем функции базы и библиотеки.

Трёхзначная логика

В JavaScript сравнение даёт true или false. В SQL — три варианта: TRUE, FALSE и NULL («неизвестно»). «Равна ли неизвестная коробка неизвестной коробке?» — неизвестно. WHERE оставляет только строки, где условие точно TRUE, поэтому строки с «неизвестно» молча выпадают. Проверять пустоту можно только через IS NULL / IS NOT NULL.

Тони Хоар, придумавший в 1965 году нулевую ссылку для языка ALGOL W, в 2009 году публично назвал её своей «ошибкой на миллиард долларов» — столько, по его оценке, стоили миру падения из-за null. А сам автор реляционной модели Эдгар Кодд позже предлагал ввести в SQL два разных NULL: «значение неприменимо» и «значение неизвестно». Не прижилось — и мы живём с одним, который означает всё сразу.

NULLIF — обратная операция

NULLIF(a, b) возвращает NULL, если a = b, иначе a. Два главных применения:

◆
ГДЕ ДЕЛЕНИЕ НА НОЛЬ ВСТРЕЧАЕТСЯ ПО-НАСТОЯЩЕМУ

Дашборд считает «конверсию» = покупки / визиты. Как это работает: для каждого фильма CASE даёт 1, если рейтинг совпал, и 0, если нет. SUM складывает единицы — получается количество. Псевдонимы в двойных кавычках — потому что "PG-13" с дефисом и заглавными (правило кавычек из урока 1).

FILTER — то же самое по-человечески (только PostgreSQL)

!
ВИДИТЕ NULL? ЭТО ЛОВУШКА ИЗ БЛОКА 02

С 2023 года в Pagila нет платежей от 5 (максимум — 4.99). SUM по пустому набору — NULL, а не 0. Исправьте сами: COALESCE(SUM(amount) FILTER (WHERE amount >= 5), 0) — и в колонке появятся нули. COUNT(*) FILTER (...) — то же, что SUM(CASE WHEN ... THEN 1 ELSE 0 END), только короче и понятнее. В MySQL и SQL Server FILTER нет — там пишут через CASE.

08 · Подзапросы: IN, EXISTS и ловушка NOT IN

live-coding~15 мин
Подзапрос — запрос в скобках внутри другого запроса. Задача решается в два шага: сначала узнать одно, потом использовать.
ВидВозвращаетГде использовать
скалярныйодно значение (1 строка × 1 колонка)в сравнении: length > (SELECT AVG(length) ...)
списочныйодну колонку, много строкfilm_id IN (SELECT film_id ...)
табличныйцелую таблицув FROM (...) AS t или через WITH (блок 09)

Скалярный

Почему не WHERE length > AVG(length)? Мы уже знаем ответ: агрегаты в WHERE нельзя, ведь WHERE работает до подсчёта. Подзапрос посчитает среднее заранее, отдельно. А вариант ORDER BY length DESC LIMIT 1 для «самого длинного» вернул бы один фильм из десяти — молча потеряв остальные девять.

IN — «входит в список, который вернул подзапрос»

film_actor — таблица связей «какой актёр в каком фильме»: в ней нет названий, только пары id. Подзапрос достаёт id, внешний запрос по ним — названия. Соединять таблицы удобнее через JOIN — это тема следующего урока, а сегодня мы решаем задачу подзапросом.

Ловушка NOT IN — разбираем на настоящих данных

Задача: «на каких языках не снят ни один фильм как на языке оригинала?». В film есть колонка original_language_id. Пишем через NOT IN и, для проверки, через NOT EXISTS:

!
ПОЧЕМУ NOT IN ВЕРНУЛ ПУСТОТУ

У всех 1000 фильмов original_language_id = NULL. Значит, подзапрос вернул список, где есть NULL. 1 NOT IN (NULL, NULL, ...) раскрывается в 1 <> NULL AND 1 <> NULL AND ..., а каждое <> NULL — это «неизвестно». Итог — «неизвестно» для каждого языка, и WHERE не пропускает ни один. Достаточно одного NULL в подзапросе, чтобы NOT IN сломался целиком, без всякой ошибки. Правило: для «нет такого» используйте NOT EXISTS. Если очень нужен NOT IN — добавьте в подзапрос WHERE ... IS NOT NULL. Это любимый вопрос на собеседовании.

09 · CTE: пишем сложный запрос по шагам

live-coding~9 мин

Подзапросы в подзапросах быстро превращаются в «матрёшку», которую никто не может прочитать:

CTE (Common Table Expression, «общее табличное выражение») — именованный подзапрос, объявленный перед основным запросом словом WITH. Как const в JavaScript: сначала дали имя промежуточному результату, потом используем.

Обратите внимание: monthly используется дважды — и в FROM, и в подзапросе со средним. Без CTE пришлось бы дважды переписывать один и тот же подзапрос.

10 · Игра «Найди баг», шпаргалка, домашка

интерактив~8 мин
SELECT customer_id, SUM(amount) FROM payment WHERE SUM(amount) > 300 GROUP BY customer_id;
Агрегат в WHERE. Фильтр групп — HAVING SUM(amount) > 300.
SELECT rating, title, COUNT(*) FROM film GROUP BY rating;
title не в GROUP BY и не в агрегате. Убрать title, добавить в GROUP BY или взять MIN(title).
Средняя оценка в отчёте «слишком хорошая»: AVG(rating), а у половины товаров оценок нет.
AVG пропускает NULL: считается только по оценённым. Если «нет оценки» должно значить 0 — AVG(COALESCE(rating, 0)). Но обычно правильнее показать рядом COUNT(rating).
Плитка «Выручка за сегодня» показывает «NaN ₽», когда продаж ещё не было.
SUM по пустому набору — NULL. COALESCE(SUM(amount), 0).
WHERE id NOT IN (SELECT manager_id FROM employees) всегда возвращает 0 строк.
В подзапросе есть NULL (у директора нет менеджера). Использовать NOT EXISTS или WHERE manager_id IS NOT NULL в подзапросе.
Отчёт «по дням» у коллеги из Алматы и у вас в Москве даёт разные суммы.
Часовой пояс сессии: date_trunc('day', ...) режет сутки по поясу сессии. Явно задать SET TIME ZONE или date_trunc('day', ts, 'Europe/Moscow').
SELECT COUNT(*) FROM ... — на фронтенде count + 1 даёт "5061" вместо 507.
COUNT — это bigint, драйвер Node.js отдаёт его строкой, и "506" + 1 склеивает строки. Number(count) или COUNT(*)::int.
CASE WHEN length < 120 THEN 'Средний' WHEN length < 60 THEN 'Короткий' ELSE 'Длинный' END — коротких фильмов 0.
Порядок условий: фильм длиной 50 уже подошёл под < 120. Узкие условия — выше.

Домашнее задание (Pagila)

Решения — в файл homework2.sql. Не забудьте SET TIME ZONE 'UTC'; в начале. Проверочные цифры — для свежей Pagila (999 клиентов).

  1. Для каждого рейтинга фильмов: количество, средняя длина и средняя стоимость замены (replacement_cost), округлённые. Оставить только рейтинги, где больше 200 фильмов. Проверка: PG-13 (223) и NC-17 (210).
  2. Выручка по годам: число платежей, сумма и средний чек. Объясните, что видно в 2022 году. Проверка: средний чек 2022 — 4.00, потом ~2.96.
  3. Сколько разных клиентов сейчас держат фильмы на руках (return_date IS NULL)? Проверка: 201.
  4. Сегментация по активности: посчитайте для каждого клиента число аренд (таблица rental), затем через CASE — «Киноман» (60+), «Регулярный» (40–59), «Иногда заходит» (меньше 40) и сколько клиентов в каждом сегменте. Используйте CTE. Проверка: 540 / 137 / 320.
  5. Сколько фильмов нет ни в одном магазине (нет записей в inventory)? Решите двумя способами: NOT EXISTS и NOT IN. Почему здесь оба способа дают одинаковый ответ, а в запросе 27 — нет? Проверка: 42.
  6. Месяцы 2025 года, в которых выручка выше средней по 2025 году. Выведите рядом и само среднее. Проверка: 8 месяцев, среднее 2187.90.
  7. Таблица «выручка по годам × сотрудник»: строки — годы, колонки staff_1 и staff_2 с суммой платежей (FILTER). Проверка: 2022 — 37896.57 и 38470.73.
  8. Со звёздочкой: средняя длительность аренды (return_date - rental_date). Почему AVG выдаёт странное 4 days 26:49:00? Найдите в документации функцию, которая это исправит.
Ответы для преподавателя
-- 1
SELECT rating, COUNT(*) AS films, ROUND(AVG(length), 1) AS avg_length,
       ROUND(AVG(replacement_cost), 2) AS avg_cost
FROM film GROUP BY rating HAVING COUNT(*) > 200 ORDER BY films DESC;
-- 2
SELECT EXTRACT(YEAR FROM payment_date) AS year, COUNT(*) AS payments,
       SUM(amount) AS revenue, ROUND(AVG(amount), 2) AS avg_check
FROM payment GROUP BY year ORDER BY year;
-- 3
SELECT COUNT(DISTINCT customer_id) FROM rental WHERE return_date IS NULL;
-- 4
WITH rentals_per_customer AS (
    SELECT customer_id, COUNT(*) AS rentals FROM rental GROUP BY customer_id
)
SELECT CASE WHEN rentals >= 60 THEN 'Киноман'
            WHEN rentals >= 40 THEN 'Регулярный'
            ELSE 'Иногда заходит' END AS segment,
       COUNT(*) AS customers
FROM rentals_per_customer GROUP BY segment ORDER BY customers DESC;
-- 5 (inventory.film_id не бывает NULL, поэтому NOT IN здесь безопасен)
SELECT COUNT(*) FROM film f
WHERE NOT EXISTS (SELECT 1 FROM inventory i WHERE i.film_id = f.film_id);
SELECT COUNT(*) FROM film WHERE film_id NOT IN (SELECT film_id FROM inventory);
-- 6
WITH monthly AS (
    SELECT date_trunc('month', payment_date) AS month, SUM(amount) AS revenue
    FROM payment
    WHERE payment_date >= '2025-01-01' AND payment_date < '2026-01-01'
    GROUP BY month
)
SELECT month, revenue, ROUND((SELECT AVG(revenue) FROM monthly), 2) AS avg_month
FROM monthly WHERE revenue > (SELECT AVG(revenue) FROM monthly) ORDER BY month;
-- 7
SELECT EXTRACT(YEAR FROM payment_date) AS year,
       SUM(amount) FILTER (WHERE staff_id = 1) AS staff_1,
       SUM(amount) FILTER (WHERE staff_id = 2) AS staff_2
FROM payment GROUP BY year ORDER BY year;
-- 8: интервал не переводит 24+ часа в дни сам. justify_interval → 5 days 02:49:00.74
SELECT justify_interval(AVG(return_date - rental_date)) FROM rental;
