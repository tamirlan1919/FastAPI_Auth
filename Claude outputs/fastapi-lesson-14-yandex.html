Интеграция с Яндексом: вход, Диск и YandexGPT

На прошлом уроке мы научились правильно ходить в чужой API на примере GitHub: один клиент на приложение, проверка ответа, честные ошибки, тесты без интернета. Сегодня применим всё это к экосистеме Яндекса и закроем три задачи, которые встречаются почти в каждом российском проекте: вход через Яндекс ID, файлы на Яндекс Диске и нейросеть YandexGPT. Главная новая тема — авторизация: у каждого сервиса свой способ доказать «мне можно», и путать их нельзя.

ЧТО ПОЯВИТСЯ В AUTH-API

  • «Войти через Яндекс»: GET /auth/yandex/login → страница Яндекса → /auth/yandex/callback → наш JWT. Новый пользователь создаётся сам, старый узнаётся по email.
  • Отчёт на Диск: POST /reports/{file_name}/yandex-disk загружает CSV из Celery-отчёта (урок 11) и возвращает публичную ссылку.
  • Авто-теги: POST /posts/suggest-tags — YandexGPT предлагает теги по заголовку поста, а если нейросеть недоступна или ответила ерундой, срабатывает запасной вариант.
  • 13 тестов трёх клиентов без интернета.

КАК ЧИТАТЬ ЭТОТ УРОК И ЧТО ПРОВЕРЕНО

В заголовке каждого блока кода написано, куда его писать. «👀 только посмотреть» — в проект не пишем. Весь код я запускал на копии вашего auth-api. Но сервера Яндекса с моего сервера недоступны, поэтому ответы Яндекса имитировал локальный сервер, написанный по официальной документации: те же адреса, заголовки, коды ответов и формат JSON. На занятии вы запустите то же самое с настоящим Яндексом: в коде меняются только ключи в .env.

01 · Как Яндекс пускает к своим API

теория~10 мин

В уроке 13 у GitHub был один вопрос: «есть ли токен?». У Яндекса (и у Google) важнее другой вопрос: от чьего имени идёт запрос. От этого зависит, какой ключ нужен.

Кто действуетЧем доказываетЗаголовокУ нас

Наш сервер как программа, без человекаAPI-ключ сервисного аккаунта Yandex CloudAuthorization: Api-Key AQVN...YandexGPT (блок 06)
!
У ЯНДЕКСА «OAUTH», А НЕ «BEARER»

Мы привыкли к Authorization: Bearer ... — так auth-api принимает свои JWT, так GitHub принимает токены. API Яндекс ID и Диска в документации требуют Authorization: OAuth <токен>, а Yandex Cloud — Api-Key <ключ> или Bearer <IAM-токен>. Перепутали слово — получили 401, хотя токен правильный. Это первое, что проверять при 401 от Яндекса.

Права доступа (scopes)

Токен даёт доступ не ко всему аккаунту, а только к тому, что вы попросили при регистрации приложения. Пользователь видит этот список на странице согласия.

ПравоЧто даётНам нужно для

login:emailадрес почтысвязать с аккаунтом auth-api
login:avatarаватаркартинка в профиле

ПРИНЦИП НАИМЕНЬШИХ ПРАВ

Просите минимум. Токен с правом «весь Диск» при утечке отдаёт злоумышленнику все ваши фото и документы, а с правом «папка приложения» — только наши CSV-отчёты. И пользователи охотнее нажимают «Разрешить», когда список короткий: «доступ ко всему Диску» ради входа на сайт пугает.

02 · OAuth 2.0 на пальцах

теория~10 мин
✦
АНАЛОГИЯ: КЛЮЧ-КАРТА В ОТЕЛЕ

Вы не даёте уборщице ключи от своей квартиры. Вы идёте на ресепшен, показываете паспорт, и вам выдают карту, которая открывает один номер и до пятницы. Так же и с OAuth: пользователь не даёт нашему сайту пароль от Яндекса. Он вводит пароль на сайте Яндекса, соглашается на «email и имя», и Яндекс выдаёт нашему серверу токен только на это и только на время.

 браузер Анны             наш auth-api                       Яндекс (oauth.yandex.ru, login.yandex.ru)
 ─────────────            ─────────────                      ──────────────────────────────────────────
 1. «Войти через Яндекс»
    GET /auth/yandex/login ──▶ создать state, положить в Redis
                          ◀── 307 → oauth.yandex.ru/authorize?client_id=…&state=…
 2. ───────────────────────────────────────────────────────▶ логин/пароль Анны, «Разрешить»
                                                            ◀ 302 → наш redirect_uri?code=4218770&state=…
 3. GET /auth/yandex/callback?code=…&state=… ──▶ проверить state (CSRF)
                                                 POST /token  code + client_secret ─────▶ access_token
 4.                                              GET /info  Authorization: OAuth … ────▶ id, login, email
 5.                                              найти/создать User, выдать НАШ JWT
                          ◀── {"access_token": "eyJ…", "token_type": "bearer"}
ШагЧто происходитПочему так
1наш сервер отправляет браузер на Яндекспароль от Яндекса вводится только на сайте Яндекса — мы его никогда не видим
2Яндекс возвращает браузер к нам с одноразовым кодомкод проходит через браузер (его видно в адресной строке), поэтому сам по себе он почти ничего не стоит
3сервер обменивает код на токен, добавляя Client secretсекрет знает только наш сервер — перехваченный код без секрета бесполезен. Поэтому этот поток и называется Authorization Code
4по токену узнаём, кто пользователь«кто ты» — это отдельный API: login.yandex.ru/info
5дальше пользователь живёт с нашим JWTтокен Яндекса нам больше не нужен: мы его не храним
!
ЗАЧЕМ STATE — АТАКА «ПОДСУНУТЫЙ ВХОД»

Без state злоумышленник может войти через Яндекс сам, остановиться на шаге 2 и прислать жертве ссылку …/callback?code=ЕГО_КОД. Жертва кликает и оказывается залогинена в чужой аккаунт. Всё, что она дальше введёт (адрес, карту, черновики), увидит злоумышленник. Это CSRF. Защита: при шаге 1 мы генерируем случайный state и запоминаем его, на шаге 3 сверяем. Чужой state мы не выдавали — отказ.

★
ФРОНТЕНДЕРАМ ЭТО ЗНАКОМО

Кнопки «Войти через Google / VK / Яндекс» на любом сайте работают именно так. Если вы когда-то подключали NextAuth (Auth.js) — внутри он делает эти пять шагов. Сегодня мы пишем их руками на бэкенде.

05 · Отчёты на Яндекс Диск

live-coding~20 мин

В уроке 11 Celery строил CSV-отчёт по пользователям, и он лежал на сервере в папке reports/. Менеджеру нужна просто ссылка: «открыл и скачал». Загрузим отчёт на Яндекс Диск и опубликуем.

Токен для Диска

Здесь действует не посетитель сайта, а мы — владелец Диска. Поэтому токен получаем один раз вручную и кладём в .env. В приложении из блока 03 уже есть право cloud_api:disk.app_folder. Откройте в браузере (подставьте свой ClientID):

После «Разрешить» Яндекс покажет токен (или вернёт его в адресной строке после #access_token=). Обратите внимание: response_type=token, а не code — это упрощённый поток, токен выдаётся сразу человеку, без обмена на сервере. Для «один раз получить свой токен» это нормально, для входа посетителей — нет.

!
ЭТОТ ТОКЕН — КЛЮЧ ОТ ВАШЕГО ДИСКА

Токен живёт долго (обычно год) и действует от вашего имени. Поэтому мы и ограничили его папкой приложения: на Диске появится Приложения/auth-api (учебный), и токен видит только её. Отозвать токен: id.yandex.ru → Безопасность → Доступы приложений.

ТРИ ПРАВИЛА ДЛЯ НЕЙРОСЕТЕЙ В БЭКЕНДЕ

1) Ответ модели — непроверенные данные, как ввод пользователя: валидируем, ограничиваем, не вставляем в SQL и HTML как есть. 2) Модель не должна быть единственной точкой отказа: всегда есть запасной путь или понятная ошибка. 3) Деньги: каждый вызов стоит денег, поэтому нужны авторизация на эндпоинте (у нас CurrentUserDep), ограничение длины и, в проде, rate limit. Иначе бот за ночь «съест» ваш грант.

07 · Синхронные SDK и asyncio.to_thread

демо~5 мин

В методичке Google API вызывается через официальную библиотеку google-api-python-client. Она синхронная, и её оборачивают в asyncio.to_thread. Так же устроены многие SDK: boto3 (Yandex Object Storage, S3), синхронный клиент библиотеки yadisk и другие. Наши три клиента на httpx асинхронные, им это не нужно. Но разницу стоит увидеть своими глазами:

Синхронный вызов прямо в async def останавливает весь event loop: пять «параллельных» вызовов идут по очереди, а «сердце» (любой другой запрос к вашему API!) не бьётся 5 секунд. to_thread уносит вызов в отдельный поток, и loop свободен. Правило: в async def только await-совместимый код; всё синхронное и долгое — через await asyncio.to_thread(функция, аргументы). Мы так и сделали с чтением файла в клиенте Диска.

!
ЛОВУШКА ИЗ МЕТОДИЧКИ

В примерах методички service = build('sheets', 'v4', credentials=credentials) вызывается в каждом запросе и вне to_thread. А build — тоже синхронный и небыстрый вызов (он собирает описание всего API). Его делают один раз при старте, в lifespan, как наши клиенты, — а в поток уносят только .execute().
