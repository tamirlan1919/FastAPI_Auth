Telegram в auth-api, часть 2: привязка аккаунта и Telethon

На прошлом уроке бот поселился внутри auth-api: Bot и Dispatcher в lifespan, polling для разработки, вебхук с секретным заголовком, колонка telegram_id. Сегодня доводим бота до дела — пользователь привязывает Telegram одной ссылкой и смотрит свой профиль и посты в чате. А во второй половине подключаем Telethon: auth-api сам читает Telegram-каналы, превращает их посты в наши посты и через бота сообщает пользователю о новых.

ЧТО ПОЯВИТСЯ В AUTH-API

  • POST /telegram/link → ссылка t.me/бот?start=код, код одноразовый, живёт в Redis 10 минут. Бот по коду привязывает Telegram к аккаунту.
  • Команды /me, /posts, /unlink — сессия БД открывается прямо в хендлере, без middleware.
  • Обработчик ошибок бота — пользователь всегда получает ответ, Telegram не повторяет апдейт.
  • POST /telegram/channels/{channel}/import — Telethon читает последние посты публичного канала, они становятся постами auth-api с тегами из хештегов. Повторный импорт ничего не дублирует.
  • POST /telegram/channels/{channel}/watch — новые посты канала приходят сами, а привязанный пользователь получает уведомление от бота. Telethon читает, aiogram пишет.
  • 8 тестов без сети и имитатор Telethon-клиента для занятия без аккаунта.

НЕ ОДНА СЕССИЯ НА ВСЁ ПРИЛОЖЕНИЕ

Соблазн — создать сессию один раз в lifespan и передать в Dispatcher(session=...). Работать будет, пока сообщения идут по одному. Два пользователя одновременно — и две корутины полезут в одну AsyncSession, а она не рассчитана на параллельную работу. Правило как в FastAPI: сессия живёт один запрос (один апдейт).

→
КОГДА ВСЁ-ТАКИ НУЖЕН MIDDLEWARE

async with в каждом хендлере — честно и понятно, но это повтор. Когда хендлеров станет двадцать, этот повтор выносят в middleware: он открывает сессию «вокруг» любого хендлера и кладёт её в аргументы. Код внутри хендлеров станет короче, а логика — та же. Сначала научитесь делать руками, потом автоматизируйте.

04 · Ошибки, повторы и логи

live-coding~8 мин

У Тимы есть пост «Шаблон ссылки: /users/<user_id>». Уберём html.quote в /posts — «там же просто заголовок» — и пока не будем ставить обработчик ошибок.

Две беды. Пользователь не получил ничего. А Telegram считает апдейт недоставленным (pending_update_count: 1) и будет присылать его снова — и каждый раз мы будем падать на том же посте.

!
ВСЁ ОТ ПОЛЬЗОВАТЕЛЯ — ЧЕРЕЗ html.quote

С parse_mode=HTML Telegram понимает только свои теги: b, i, u, s, code, pre, a, blockquote, tg-spoiler и ещё несколько. <user_id> для него неизвестный тег, и он отклоняет всё сообщение. Заголовки, username, email, текст из чужого API — всё через html.quote(). Та же идея, что защита от XSS на фронтенде.

Пользователь получил ответ, в логе полный traceback с update_id, вебхук ответил 200 — повторов не будет. Возвращаем html.quote.

05 · Telethon: MTProto, вход и строка сессии

теория + практика~12 мин

Всё, что делал наш бот, — это Bot API: HTTP-обёртка, которую Telegram сделал специально для ботов. Приложение Telegram на телефоне говорит с серверами по другому протоколу — MTProto. Telethon — клиент MTProto на Python: ваш код входит в Telegram как обычный пользователь, по номеру телефона.

✦
АНАЛОГИЯ: ОПЕРАТОР И СОТРУДНИК С ПРОПУСКОМ

Бот — оператор колл-центра: отвечает тем, кто позвонил, и работает по инструкции. Telethon — сотрудник с вашим личным пропуском: может зайти куда угодно, куда можете вы. Удобно, но если пропуск украдут или сотрудник начнёт хулиганить, отвечать будете вы своим аккаунтом.

Задача на сегодня

Пользователь auth-api говорит: «вот канал @fastapi_news, хочу его посты у себя». Мы (1) импортируем последние посты по кнопке и (2) подписываемся на канал, чтобы новые посты приходили сами, а бот написал пользователю «новый пост». Бот прочитать чужой канал не может — нужен Telethon.

Вход: api_id, api_hash и строка сессии

  1. my.telegram.org → войти по номеру → API development tools → создать приложение (название любое, платформа Other) → api_id (число) и api_hash (32 символа). Это ключи приложения, не аккаунта.
  2. Войти в аккаунт из кода один раз и сохранить результат.

Код придёт не SMS, а сообщением в приложение Telegram на телефоне — от служебного аккаунта «Telegram».

СТРОКА СЕССИИ = ВАШ АККАУНТ

Кто получил TELETHON_SESSION (или файл .session), тот читает вашу переписку и пишет от вашего имени — без пароля и кода. В git, Docker-образ, скриншот, общий чат — никогда. ОДИН ПРОЦЕСС — ОДНА СЕССИЯ

Одну строку сессии нельзя использовать в двух процессах одновременно: Telegram увидит один «вход» с двух мест, и соединения начнут мешать друг другу. Значит: uvicorn --workers 4 с Telethon в lifespan — плохо. В проде Telethon выносят в отдельный процесс (воркер), а API общается с ним через очередь — как email_worker из урока 10. На занятии один процесс, так проще.

live-coding~12 мин

Самое интересное: Telethon слушает каналы, auth-api создаёт посты, а aiogram-бот пишет пользователю. Два клиента Telegram в одном приложении, каждый делает то, что умеет.

☺
ПОЧЕМУ TELETHON НЕ МОЖЕТ ПРОСТО ПИСАТЬ САМ

Аккаунт Telethon тоже умеет send_message. Но тогда уведомления приходили бы от «Тимы-человека», а не от бота, и каждое сообщение незнакомцу — шаг к блокировке. Разделение честное: аккаунт читает, бот пишет тем, кто его сам запустил.

09 · Имитатор клиента и тесты

демо~5 мин

Telethon требует настоящий аккаунт, а в тестах и на занятии без аккаунта его нет. Поэтому клиент — класс с понятным интерфейсом (start, latest_posts, join, on_new_post, stop), и его можно подменить. В архиве — scripts/fake_channels.py:

  • канал fastapi_news с пятью сообщениями — это настоящие объекты telethon.tl.types.Message, они идут через тот же message_to_post;
  • durov — «не канал», flood_test — FloodWaitError на 37 секунд;
  • python -m scripts.fake_channels запускает auth-api с имитацией вместо Telethon, а POST /_fake/channels/{канал}/post публикует новый пост.

10 · Игра «Что пошло не так?», шпаргалка, домашка

интерактив~8 мин
Ссылка привязки сработала два раза — с двух телефонов.
get + delete вместо GETDEL (или delete забыли совсем). Код должен «сгорать» атомарно.
Кто-то отвязал чужой Telegram одним curl, не зная ни пароля, ни телефона.
Вебхук без проверки X-Telegram-Bot-Api-Secret-Token. from.id — просто поле в JSON.
Под нагрузкой бот падает с ошибками SQLAlchemy про параллельные операции в сессии.
Одна AsyncSession на всё приложение. Сессия — на апдейт: async with async_session_maker() в хендлере.
/posts у одного пользователя молчит, а pending_update_count растёт.
Хендлер падает → вебхук 500 → Telegram повторяет апдейт. Заголовок с <…> без html.quote + нет dp.errors.
Добавили fallback.router первым — бот на всё отвечает «Не понял».
Порядок роутеров. Пустой @router.message() ловит всё. Fallback — последним.
auth-api при старте висит и в логах сервера просит «Please enter your phone».
client.start() в lifespan без авторизованной сессии. Входим один раз скриптом, в приложении — connect() + is_user_authorized().
Запустили uvicorn --workers 4 — Telethon начал отваливаться с ошибками авторизации.
Одна строка сессии в четырёх процессах. Telethon — в одном процессе (отдельный воркер).
Импорт канала второй раз создал те же посты заново.
Нет учёта импортированного. SADD tg:imported:<user> канал:id — 0 значит «уже было».
Подписались через /watch, но новые посты не приходят. Импорт при этом работает.
Аккаунт не вступил в канал (или вышел). Обработчик событий видит только каналы, где аккаунт состоит, — поэтому /watch делает JoinChannelRequest.
Строку TELETHON_SESSION закоммитили в публичный репозиторий.
Аккаунт скомпрометирован. Сразу: Telegram → Настройки → Устройства → завершить этот сеанс; удалить строку из истории git; создать новую сессию.
